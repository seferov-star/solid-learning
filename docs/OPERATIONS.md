## VPS

Проект на VPS магазина: `/opt/solid-learning/compose.yml`. Контейнер `solid-learning-api` принимает запросы на `127.0.0.1:8082`. При переносе запущен образ `solid-learning:shop-f583147`, собранный из коммита `f583147` с зависимостями из `package-lock.json`. Данные хранятся в `/srv/solid-learning/data/app.sqlite`, каталог смонтирован в `/app/data`. У магазина отдельные контейнеры и база. Лимиты API — 512 МБ и 0,75 vCPU.

Проверки: `docker inspect solid-learning-api`, `docker logs --tail 50 solid-learning-api`, `systemctl list-timers solid-learning-backup.timer`. HTTP health: `/api/v1/health`.

Ежедневная копия SQLite создаётся `solid-learning-backup.timer` в `/srv/solid-learning/data/backups`. Снимок перед переключением хранится в `/var/backups/solid-learning/pre-migration.sqlite`. HTTPS и продление сертификата обслуживает Caddy. Маршрут API задан в `/etc/caddy/solid-learning-api.caddy`.

## Обновление и откат

1. Проверить тесты и дождаться CI. Сборка Pages публикуется отдельно, API image выгружается артефактом api-image.
2. tools/download-image.py скачивает OCI-архив. Перед загрузкой в Docker сверить SHA256 локального файла и копии VPS.
3. Снять резервную копию командой `systemctl start solid-learning-backup.service`.
4. Обновить тег `image` в `/opt/solid-learning/compose.yml` и выполнить `docker compose -f /opt/solid-learning/compose.yml up -d api`. Проверить HTTPS, вход и отправку ответа.
5. Для отката вернуть предыдущий тег. При несовместимой миграции остановить api, отдельно сохранить текущую БД со всеми WAL/SHM, восстановить резервную копию, затем запустить предыдущий образ. Не восстанавливать БД поверх работающего приложения.
6. Если потребуется вернуться на HqServ, после появления новых ответов сначала перенести актуальный снимок SQLite обратно. Затем вернуть адрес API в `.github/workflows/publish.yml` и дождаться публикации Pages.

## Устойчивость к задержкам и обрывам

useAttemptConnection отделяет фоновое обновление от записи ответа. Опрос не перекрывается: 10 секунд после завершения предыдущего, 30 секунд на паузе, задержка при ошибках до 60 секунд. Скрытая вкладка не опрашивает сервер; возвращение/online запускают сверку. Пользовательское действие отменяет GET, устаревшие ответы и ошибки отбрасываются. Таймер рисуется локально с периодической сверкой; окончательный срок и оценка проверяются сервером. При достижении нуля инициируется дополнительная сверка.

Выбранный ответ до подтверждения — небольшая временная запись sessionStorage, scoped по API и user ID (attemptId/itemId/optionId). Это очередь доставки, не локальная статистика. POST answer имеет ограниченный срок ожидания; при потере ответа сначала GET/readback, повтор только если сервер ещё ждёт этот вопрос, строго с прежними ID. Есть ручное восстановление, повтор после online/focus и удержание выбора после reload той же вкладки. После закрытия вкладки sessionStorage не сохраняется. Серверные квитанции receipts содержат только ID уже выбранных вариантов, без правильности; экзаменационные ключи по-прежнему скрыты. Иные POST автоматически не повторяются; после обрыва next/pause/finish читается текущее состояние.

Обычный Store.view больше не записывает полный JSON попытки на каждом опросе: время вычисляется от последней сохранённой отметки. Значимые действия и серверные timeout-переходы сохраняются. Worker проверяет сроки без формирования полного UI-ответа. Схема данных и версии учебных курсов не меняются.

API nginx: keepalive_requests=100, keepalive_timeout=30s вместо закрытия после каждого ответа. Предыдущая конфигурация сохранена на VPS в /home/serfer/solid-learning/nginx-before-reliability.conf. В контрольной пробе после первого TLS-подключения 6.92 секунды следующие 5 запросов переиспользовали соединение и ответили за 22–29 мс. Это разовая проверка механизма, не обещание постоянной задержки: исходная сеть продолжала периодически задерживать установление новых соединений.

CORS preflight кэшируется на 300 секунд. Ответы имеют X-Request-ID; сообщения api_timing для answer/медленных/ошибочных запросов содержат только UUID запроса, шаблон маршрута, метод, статус и длительность, без токенов, паролей и тел запросов. Docker-логи ограничены 3 файлами по 5 МБ. Эти замеры позволяют отделить обработку на API от доставки по сети.
