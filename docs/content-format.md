# Формат учебного банка v1

Внутренний контракт: `{ "schemaVersion": 1, "course": { ... } }`.

`course`: id (латиница/цифры/дефис), title, shortTitle, subtitle, edition, sourceUrl, pdf, topics, items, examEnabled, timedPractice, exam.

`topics`: массив `{id,title,description,sectionRef}`. В каждом разделе нужны вопросы и кейсы.

`items`: массив `{id,topicId,kind,difficulty,question,wolfContext,options,correctIndex,explanation,clauseRef,sourcePage}`. `kind`: question/case; `difficulty`: easy/medium/hard. Ровно четыре различных непустых варианта `options`; `correctIndex`: 0..3 в исходном порядке. Необязательные поля: sourceClause, sourceExcerpt, sourceAnchor, optionReasons (четыре пояснения в том же порядке).

ID вопроса/кейса стабилен. При изменении смысла или правильного ответа используйте новый ID, чтобы прежний зачёт не переносился на иное задание. Редакционные правки не требуют нового ID. В рамках попытки сервер генерирует устойчивые идентификаторы вариантов и сохраняет порядок; клиент отправляет ID варианта, а не числовой балл.

`exam`: `{count,seconds,passPercent}`. Для доступного экзамена count не меньше числа разделов и не больше числа вопросов. `examEnabled:false` отключает экзамен независимо от индивидуальных разрешений. timedPractice включает тренировку кейсов с таймером.

Проверка: `validateContent(document)` в server/content.ts. Публикация версии: `store.publishContent(document, adminId)`. Метод проверяет роль и формат, создаёт неизменяемую версию и меняет активную; операция записывается в журнал. В v1 HTTP-маршрута загрузки и редактора нет. Первоначальные три курса загружаются при создании БД; перезапуск не откатывает опубликованную версию.

Данные попытки закреплены за версией. Новые задания не меняют завершённые результаты; допуск к новым экзаменам пересчитывается по текущему банку. Ручное разрешение пользователя действует на тему, а отсутствие экзамена у темы имеет приоритет.
